# Local design workspace

Opening a repository lands on Project Home. Existing Page opens the chosen screen; Feature Flow opens the checked pages in selection order and connects them. Blank Design creates an editable frame using the project's detected CSS and assets. Design files and folders remain separate from application routes.

The workspace provides project pages, native UI patterns, project components, image/font assets, layers, an inspector, and a freeform canvas. Frame selection supports shift selection, marquee selection, dragging, resizing, duplication, grouping, locking, alignment, snapping, and arrow-key nudging. Space pans; Ctrl/Cmd + wheel zooms around the pointer. F creates a frame. Ctrl/Cmd + D duplicates, Ctrl/Cmd + G groups, Shift + Ctrl/Cmd + G ungroups, and Shift + Ctrl/Cmd + L toggles frame locking.

Layout guides provide columns, gutters, margins and opacity. They are overlays and are excluded from design trees. Responsive frame widths use detected CSS breakpoints and token values; conventional viewport dimensions are a fallback when no matching rule is available. Project container widths constrain design surfaces unless Overflow Container is enabled. Responsive copies have independent design states.

## Rendering and limits

Live pages run the imported application locally. Generic PHP uses script URLs and an available loopback port. Framework views without a public route, and PHP routes that fail to render, can display their parsed source and local styles instead. Parser-version invalidation refreshes older indexes.

Duplicate to design captures the rendered DOM and its observed styles when available. Source-only designs render safe native HTML from parsed structure. Project native UI patterns preserve their source classes; observed project styles and safe text/attribute changes can be edited. Dynamic framework components, unresolved template expressions, application-dependent props, and server data still require the real running application for full fidelity. Detected application-dependent props are informational, not simulated controls. Imported source files are not rewritten by canvas edits.

Embedded editable surfaces disable scripts, forms, navigation and network resources. Supported images and fonts are embedded from bounded files inside the project. Styles are read from CSS files, not generated by executing a project's build. Source-only previews cannot resolve every CSS preprocessor, framework runtime, include or inherited layout. The source asset bundle is bounded to keep large repositories usable.

Design trees, semantic changes and their existing feature/version records use FrameUI's local workspace files. Folders, design-file metadata, frame geometry, guides, connections and camera positions use project-keyed Electron local storage. No upload, remote design service or cloud synchronization is introduced.

## Verification

- `npm run typecheck`
- `npm run lint`
- `npx bun test`
- `npx vite build`
- `node scripts/smoke-workspace.cjs`

The desktop smoke check needs a graphical Electron environment and PHP. It imports a temporary fixture, verifies that its own local server serves the correct project, opens a two-screen flow, edits and reopens a captured design, inserts a real project button into a blank design, enables guides, and creates responsive copies. It uses an isolated application profile and stops its preview process afterward. Screenshots are written to the operating system's temporary directory.
